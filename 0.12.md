**Version:** 0.12
**Date:** 2026-05-22

## 1. Purpose

The NSG prototype corpus (0.11.py, 25 documents across 5 languages) demonstrates the search architecture but is hand-constructed. A production evaluation requires real parallel texts — the same proposition expressed in multiple languages — to validate the language-neutrality claim on authentic data. This document specifies the format, sources, and collection strategy for such a corpus.

## 2. Parallel Text Format

### 2.1 Core Structure

```
proposition_id: str           # unique identifier for the semantic proposition
languages:                    # one entry per language
  English:
    surface: "The dog bit the man yesterday"
    morph_segmented:          # morpheme-level segmentation
      - {morpheme: "the", gloss: "DEF"}
      - {morpheme: "dog", gloss: "dog.NOM"}
      - {morpheme: "bite", gloss: "bite.V"}
      - {morpheme: "-ed", gloss: "PAST"}
      - {morpheme: "the", gloss: "DEF"}
      - {morpheme: "man", gloss: "man.ACC"}
      - {morpheme: "yesterday", gloss: "yesterday.ADV"}
    nst:                       # expected NST structure
      nodes: [...]
      edges: [...]
  Turkish:
    surface: "Köpek adamı dün ısırdı"
    morph_segmented: [...]
    nst: {...}                 # identical to English NST
  Mohawk:
    surface: "..."
    morph_segmented: [...]
    nst: {...}                 # identical NST
```

### 2.2 Design Principles

1. **The NST is the invariant.** All language entries for the same proposition must produce isomorphic NSTs.
2. **Gradual coverage.** Start with 5 propositions, expand to 50, then to 500+.
3. **Typological diversity.** Each proposition should have entries in at least one isolating, one agglutinative, and one polysynthetic language.
4. **LLM-INFERRED labeling.** All morphological segmentations generated without native speaker verification must be labeled `[LLM-INFERRED]`.

## 3. Existing Resources

### 3.1 Parallel Corpora

| Resource | Languages | Format | Relevance |
|:---------|:----------|:-------|:----------|
| **Parallel Bible** | 1000+ languages | Verse-aligned | HIGH — identical propositions across languages. Turkish, Finnish, Inuktitut available. Mohawk: partial. |
| **Universal Dependencies** | 100+ languages | Dependency trees | HIGH — pre-parsed dependency structures map to NST edges. Turkish, Finnish, English available. |
| **WALS (World Atlas of Language Structures)** | 200+ languages | Typological features | MEDIUM — provides mandatory feature cluster data. Useful for semantic prime assignment. |
| **Tatoeba** | 400+ languages | Sentence-aligned | MEDIUM — community translations. Quality varies. |
| **OPUS (open parallel corpus)** | 90+ languages | Sentence-aligned | MEDIUM — includes EU parliament, subtitles, software localization. |

### 3.2 Language-Specific Resources

| Language | Universal Dependencies | Parallel Bible | Other |
|:---------|:----------------------|:---------------|:------|
| English | Yes (EWT, GUM, PUD) | Yes | Extensive resources |
| Turkish | Yes (IMST, BOUN, PUD) | Yes | Zemberek integration possible |
| Finnish | Yes (TDT, PUD) | Yes | HFST/Omorfi integration possible |
| Mohawk | **No** | Partial | Only descriptive grammars exist |
| Inuktitut | **No** | Yes (partial) | Uqailaut FST for morphological analysis |

### 3.3 Gap: Mohawk and Inuktitut

The primary gap is **morphologically annotated parallel text** for polysynthetic languages. While Parallel Bible verses exist in Inuktitut (syllabic script) and Mohawk (Latin orthography), they lack morpheme-level segmentation. Creating such segmentation requires:
- Native speaker or linguist expertise for verification
- Morphological analyzer (exists for Inuktitut at research stage; does not exist for Mohawk)

## 5. Integration with NSG Pipeline

### 5.1 Corpus Processing Pipeline

```
Parallel text (JSON)
    │
    ▼
Per-language morphological analysis
    │  ├── English: spaCy tokenization + lemmatization
    │  ├── Turkish: Zemberek FST
    │  ├── Finnish: HFST/Omorfi
    │  ├── Inuktitut: Uqailaut FST (where available)
    │  └── Mohawk: manual segmentation (gap)
    │
    ▼
NST construction (per 0.10.py pipeline)
    │
    ▼
Corpus index (per 0.3.md §7.1)
    │
    ▼
Evaluation: precision@k, recall@k, MRR (per 0.10.md)
```

### 5.2 Validation Protocol

1. **Structural validation:** All NSTs for the same proposition must be isomorphic (identical distance matrices).
2. **Search validation:** A query in language L₁ must return the parallel text in language L₂ as a top result.
3. **Ultrametric validation:** All NSTs in the corpus must satisfy the ultrametric inequality with zero violations.
