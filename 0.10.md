# Evaluation Framework for Sub-Graph Search on Nested Semantic Graphs

**Version:** 0.10
**Date:** 2026-05-22
**Depends on:** 0.3.md (Search Spec), 0.10.py (Turkish Pipeline)

## 1. Motivation

Keyword search has well-established evaluation metrics (precision@k, recall@k, MRR, NDCG). Sub-graph matching search requires adapted versions of these metrics because the unit of relevance is not a term match but a structural match between semantic trees. This document defines the evaluation framework for the NSG search architecture.

## 2. Metrics

### Precision@k

Fraction of top-k results that are relevant:

$$P@k = \frac{|\{\text{top-}k \text{ results}\} \cap \{\text{relevant documents}\}|}{k}$$

### Recall@k

Fraction of all relevant documents found in top-k:

$$R@k = \frac{|\{\text{top-}k \text{ results}\} \cap \{\text{relevant documents}\}|}{|\{\text{relevant documents}\}|}$$

### MRR (Mean Reciprocal Rank)

Reciprocal rank of the first relevant result:

$$\text{MRR} = \frac{1}{\text{rank}_{\text{first relevant}}}$$

### Relevance Definition

A document is **relevant** to a query if its NST contains a Type I, Type II, or Type III match. Relevance is binarized: Type I/II matches with coverage >= 0.5 are relevant; Type III matches with edit distance within threshold are relevant. For the prototype threshold, Type III matches with score >= 0.5 are considered relevant.

### Ultrametric-Specific Measures

Because the ultrametric inequality guarantees nested result clusters, we also define:

- **Cluster Precision:** Fraction of results within the top cluster that are relevant
- **Cut Point Quality:** Whether the automatic cluster boundary separates relevant from irrelevant results

## 4. Limitations

- Small corpus (3 documents) limits statistical significance
- Binarized relevance simplifies the continuous score spectrum
- No inter-annotator agreement for relevance judgments
- Evaluation on synthetic/hardcoded relevance, not human judgments
